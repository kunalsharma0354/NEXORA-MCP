# UI/UX & Design Systems

Create coherent, usable product interfaces with clear hierarchy, reusable design tokens, and polished interaction states.

## When to use
Use when designing or improving screens, dashboards, forms, onboarding, navigation, or component systems.

## Design process
1. Understand audience, primary task, content hierarchy, and success state.
2. Inspect existing design tokens, components, screenshots, and product conventions.
3. Choose a consistent layout grid, spacing scale, type scale, color roles, radii, borders, and elevation; reuse existing tokens.
4. Prioritize information hierarchy and task completion over decoration.
5. Design empty, loading, error, disabled, hover, focus, active, and success states—not only the ideal screenshot.
6. Make layouts responsive with content-driven breakpoints and graceful behavior for long labels and dense data.
7. Use meaningful icons consistently and do not rely on icon-only controls without accessible names.
8. Prefer restrained motion that supports feedback and respect reduced-motion preferences.

## Dashboard guidance
- Put the primary action and page purpose first.
- Use summary cards only when the metrics are meaningful and sourced.
- Avoid fake counts, decorative charts with invented data, and excessive cards.
- Keep filters, search, table actions, and pagination understandable.
- Provide clear empty states with a relevant next action.

## Accessibility
- Maintain sufficient contrast, visible keyboard focus, semantic headings, labelled fields, and keyboard-accessible menus/dialogs.
- Do not use color as the only status indicator.
- Preserve usability at zoom and narrow viewports.

## Review checklist
- Does the primary task stand out?
- Is spacing consistent?
- Are typography and contrast readable?
- Does each visible control do something real?
- Are all key states designed?
- Does the UI match the existing product rather than introduce an unrelated style?

## Avoid
Do not equate “modern” with gradients, glass effects, animations, or cards everywhere. Use visual effects only when they improve clarity and fit the product.

## Final response
Summarize what changed, relevant files or components, checks actually run, results, and any remaining limitations. Be concise, specific, and honest.
